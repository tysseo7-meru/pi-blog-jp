Featuring New SoloHost Apps: OpenClaw and Atlassian MCP Server

Published: August 27, 2026

Categories: developer, update

Original article

This page is a plain-English summary of an article from the official Pi Network blog. It is not a full translation. Difficult words and expressions are explained in simple words. For the exact wording, see the original article.

The OpenClaw and Atlassian MCP Server apps are now featured in SoloHost in Pi Desktop (a system that makes it easy to install and run self-hosted apps, meaning apps you run yourself). This widens the range of useful software that users can install and run more easily on their own computers.

These two apps, released together with Node version 0.6.2, show that SoloHost can support different needs: from AI agents that run in your own place (a setup where AI does work on its own) to more specialized AI-connected workflows.

With SoloHost, users can find, evaluate, install, and run self-hosted apps through Pi Desktop, without having to set up the technical base behind them — servers or Docker (a system for running apps in isolation) — in fine detail by hand. OpenClaw is an AI agent that runs in your own place. It can run on a local model, or on outside models such as ChatGPT and Claude. The Atlassian MCP Server app, on the other hand, provides a locally run MCP server, for connecting supported AI tools with Jira, which organizes workflows.

OpenClaw on SoloHost: local AI that is simpler and more closed off

OpenClaw is an AI agent that runs in your own place: it runs on the user's own computer and helps with their work. On a computer that meets the performance requirements for running an agent on a local AI model, OpenClaw lets users control more strongly how it works with their data and computing environment, and can reduce dependence on distant infrastructure for supported tasks. If, instead, a cloud model such as Claude or ChatGPT is used, the requests sent to that model are processed on the model provider's infrastructure. In either setup, OpenClaw's memory is created and stored on the user's computer.

When OpenClaw runs through SoloHost, it runs inside a container (a box that runs an app in isolation), designed to limit standard access to the wider computer. Compared with installing it directly outside SoloHost, where it may by default be given wider access to the whole computer, such as the local file system, this is a more closed setup: whether the configured model is local or in the cloud, there is less exposure of unrelated local files and system resources.

This closed setup does not remove all risk, and it does not cancel permissions that the user clearly gave. If a user allows OpenClaw to access outside services or resources, the agent can still act within the scope of that permission. The benefit of the SoloHost setup is more specific: it limits unnecessary default access to other parts of the user's own computer, while letting the user give the clear permissions needed for a specific task.

SoloHost also makes setting up OpenClaw simple. It automatically packages the app and the environment it needs so they can be used through Pi Desktop, reducing the amount of setup that users would otherwise have to handle by hand.

With OpenClaw added, alongside Hermes, an already released AI agent that runs in your own place, the choices of locally running AI agents available through Pi Desktop have widened. OpenClaw puts weight on being a personal helper connected to tools and the whole messaging path, while Hermes puts more weight on lasting memory and learning skills from experience.

Atlassian MCP Server on SoloHost: connecting AI workflows with Jira

The Atlassian MCP Server on SoloHost meets more specialized needs: developers, product teams, and other professionals who want to build AI tools into their own Jira workflows.

For AI tools to work with a service like Jira, there needs to be a way for the two systems to communicate. The Model Context Protocol, or MCP (a set of rules for connecting AI tools with outside systems), provides a framework for supported AI tools to connect, through an MCP server, to outside systems such as Jira.

Atlassian (Jira) offers its own hosted MCP option. But when teams use it for internal AI-connected Jira workflows, they may hit limits (quotas) or stability restrictions. The SoloHost app here meets the needs of teams that hit such limits: it lets users run their own MCP server in their own place, without being limited by quota or stability problems.

Specifically, with the Atlassian MCP Server on SoloHost, the user's own computer, or a machine of their choice, can run the server locally. AI tools that support MCP connect through that local server and can work in Jira. Because the connection is based on MCP rather than on a specific AI system, it can work with different MCP-supporting AI tools, such as Cursor, Claude Desktop and Claude Code, and Codex. This can make organizing work in Jira more automatic and smarter.

Expanding SoloHost's usefulness for Pioneers and the Pi ecosystem

OpenClaw and the Atlassian MCP Server show that SoloHost can support different kinds of self-hosted software for different user needs, from AI agents that run in your own place to more specialized developer tools.

This gives Pioneers (Pi users) more ways to use their own computers for local AI, easier access to other self-hosted apps, and widens the usefulness of Pi Desktop and Nodes (computers that support the network) beyond the blockchain base. Through SoloHost, people can receive the benefits of AI while keeping more of their data and computing on their own devices, and reducing dependence on third-party distant infrastructure.

At the same time, these two apps show that developers can build various tools and bring them into the Pi ecosystem, where they can reach more than 420,000 Pi Node operators and a larger number of Desktop users.

As the number of self-hosted apps grows, SoloHost can keep expanding the role of Pi Desktop as a system for practical tools, and increase the ways users can benefit from the computing resources they already run.

SoloHost is still in beta (a trial version) and uses a permissionless release flow. Users should evaluate each package (a complete set of an app) and install it at their own responsibility.
