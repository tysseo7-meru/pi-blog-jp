Pi Adds New Developer Capabilities and Releases New Documentation For Developers

Published: September 4, 2026

Categories: developer, update

Original article

This page is a plain-English summary of an article from the official Pi Network blog. It is not a full translation. Difficult words and expressions are explained in simple words. For the exact wording, see the original article.

Pi introduced new features for developers building on Pi. They are support for local storage (storage on the user's device), access to staking data for each app in Ecosystem Directory Staking (the system for staking in the list of Pi apps), and sharing of files and videos. Pi's new developer documentation was also released. The technical materials are now gathered in one place, and the path from getting started to building and publishing an app is clearer.

Together, these updates widen the tools developers can use. They also improve the documentation and the guidance for taking part that support development on Pi.

Support for local storage (storage on the device)

Pi added support for local storage in the Pi Browser, at first for some apps on an allow list (a list of apps that are allowed; also called a whitelist). This lets those apps keep certain data directly on a Pioneer's (a Pi user's) device. This is one way Pi reduces the cost and effort of building on the network.

Settings, session state (the state while you are using an app), and other data that fits local storage can be kept on the device. Developers do not need to store and deliver that data from their own back-end system (the system behind the app that users do not see). This helps reduce the related base costs.

The Pi Browser manages this data for the app. The contents are not sent to Pi's servers and stay on the Pioneer's device, so that data stays private on the device. This support is designed to give a more consistent storage experience on both iOS and Android. Because the data is stored on the device, it stays tied to a specific account and device. It does not follow the user across devices on its own.

To use this feature, an app must first be on the allow list. In the current system, apps on the allow list share a limited storage space on the device. When that storage space becomes full, old data may be removed. For that reason, local storage is not meant to be used as a place where storage is guaranteed to last forever. Turning the feature on app by app adds extra care and limits to its first use. It also lets Pi check performance and storage behavior across devices, storage conditions, and real patterns of use.

Staking Data API

Pi also introduced a Staking Data API (a way for outside programs to get data). With it, developers can see the effective amount that users have staked (Pi put in to support an app) for their app through the Ecosystem Directory Staking feature. The effective stake takes into account both the amount of Pi staked and an extra amount based on how long it was staked.

This API returns a user's effective stake only for the app that asked for it. So developers can get staking information for each app and build it into their own app.

Access to this API also requires, at first, that the app that asks is on the allow list. This helps make sure that trials and opinions from developers and Pioneers in the first period can help guide how the API develops in the future.

File and video sharing feature

Developers can now use Pi.shareFile to let users share files, including videos, from their apps.

This gives developers one more feature they can build into apps that need a file-sharing feature, and it supports a wider range of app experiences. Examples of use include a marketplace app (an app for buying and selling) where a Pioneer shares a receipt or images of an item in a dispute, and a game or content app where a user shares an image or a video clip directly from the app. By using the sharing feature that is already on the phone, developers can add these experiences without building a separate sharing flow themselves.

Release of improved developer documentation

Pi's new developer documentation was released. The materials for developers building on Pi are now gathered in one place, and the developer experience was improved.

Before, Pi's developer documentation was split across several places. These included the SDK documentation (documentation for a set of development parts), the Community Developer Guide, and a GitHub documentation repository (a place where files are stored). Materials sometimes overlapped. Developers who came in through different Pi web pages or other routes could reach different sources of information.

The new site gathers the developer documentation on one domain owned by Pi (a site address), and reorganizes it along the developer's path. Developers can follow a clearer path, from getting started and registering an app, through development in a sandbox (an environment for testing), adding Pi features, and preparing an app for publication.

In addition to the reorganization, the new documentation also adds more detail and explanations about parts of the system that community developers had said were unclear before. As a way to get started with Pi development, the documentation covers account and app registration, sandbox setup, SDK and system references, identity verification and payments, and the path from sandbox development to Mainnet (the real, live network) and publication. It also introduces AI guidance for adding identity verification and payments.

The documentation has been reviewed against how the current system works. It helps developers use one up-to-date source of information when they build.

Supporting development across the whole Pi ecosystem

Developer tools are an important part of Pi's larger focus on usefulness, because they directly affect the kinds of apps and services developers can create on Pi. Local storage, staking data for each app, and file sharing each add parts that developers can build into their apps. Clearer documentation and guidance, gathered in one place, make it easier to understand and put into practice the features available in Pi's developer system.

Supporting developers is essential to widen usefulness at the app level. Developers create products, services, and experiences that give Pioneers more ways to take part in the Pi ecosystem. Improving the base development environment helps turn Pi's technical features and ecosystem resources into apps that Pioneers can use.

As the Pi ecosystem keeps supporting a wider range of apps, these improvements to developer tools and documentation help lower the real barriers when developers keep building apps in the Pi ecosystem.
