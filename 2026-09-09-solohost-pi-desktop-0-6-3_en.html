SoloHost Updates in Pi Desktop Version 0.6.3: Improved App Discovery, Reliability, and Developer Tools

Published: September 9, 2026

Categories: developer, update

Original article

This page is a plain-English summary of an article from the official Pi Network blog. It is not a full translation. Difficult words and expressions are explained in simple words. For the exact wording, see the original article.

An update to SoloHost (a system that lets you install and run self-operated apps from Pi Desktop) has been released together with Pi Desktop version 0.6.3. The contents are improvements to app discovery and management, improvements to app stability, and improvements to the developer tools for building SoloHost apps and examining problems.

Note that from version 0.6.3, these releases will be called Pi Desktop versions, not Pi Node versions.

SoloHost updates included in Pi Desktop 0.6.3

  • Ranking of SoloHost apps based on the number of people running them: community SoloHost apps are now ranked based on the number of people currently running that app. This makes active community apps stand out within SoloHost, and makes it easier for Pioneers (Pi users) to find apps that other people are actually using
  • A new "My Apps" section: a new "My Apps" section has been added to the SoloHost home screen, showing the apps the current user has published. Developers and publishers gain a dedicated place to find and manage their own SoloHost apps
  • SoloHost app readiness checks (readiness probes): a readiness check confirms the state of a SoloHost app and helps avoid the 502 errors (a kind of server-side response error) that sometimes occur due to connection and similar problems. This lets SoloHost judge better whether an app is ready and responding correctly, and raises the stability of the app experience
  • Improved Docker Compose support for examining problems: technical users who want to work on the command line (the screen where you type commands as text) can move to the installation folder and run the standard docker compose up and docker compose down commands outside SoloHost. This gives another way to try starting and stopping containers (boxes that run apps in isolation) and to examine problems when needed
  • A new SoloHost developer contract: the first SoloHost repository (a place where files are kept) has been prepared to help developers build SoloHost apps. This repository is in a form that AI agents (systems where AI works autonomously) can understand easily, so AI can help developers create SoloHost apps more effectively
  • Bug fixes: a fix to the SoloHost login token and a fix to the display of long image names are included

In the fix to the SoloHost login token, a problem was fixed where, if Pi Desktop was left running for many days, the SoloHost login token (a code showing the login state) would expire. In the fix to the display of long image names, a display problem where long image names overflowed the display frame was fixed, so they now wrap correctly. In the original article, these two fixes are explained twice: once in the list, and again in more detail right after it.

Taken together, these updates make SoloHost stronger as the number of self-operated apps in the ecosystem grows. If apps become easier to find and more stable, Pioneers can find and run useful apps more easily, and if there are new developer materials and problem-examining options, developers can keep building apps for SoloHost easily.

These improvements support SoloHost's larger role of widening the usefulness of Pi Desktop and nodes (computers that support the network) beyond the blockchain foundation. They give Pioneers more ways to use their own computers for self-operated apps, and give developers more tools to build apps and bring them into SoloHost.
